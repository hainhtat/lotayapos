## Current findings

### AUTH-01 — High — Global refresh-rate bucket locks out all sessions

**Location:** `backend/src/middleware/auth-rate-limit.ts:45-67`; `backend/src/routes/v1/auth.routes.ts`

**Evidence:** The generic limiter always increments both an IP bucket and an account bucket. It derives the account from `req.body.identifier` or `req.body.email`; refresh requests carry only a refresh token (or cookie), so every refresh uses the literal identifier `"missing"`. `refreshRateLimit` allows 30 attempts per 15 minutes, meaning the 31st aggregate refresh across all users is rejected regardless of IP or account.

**Failure scenario:** More than 30 riders/admin browser sessions refresh within one 15-minute window. The shared account counter crosses the threshold and every subsequent refresh on that API process receives 429 until reset. Normal synchronized access-token refreshes can trigger this without an attacker.

**Impact:** System-wide session refresh outage, repeated login prompts, and interruption of rider/finance workflows. Restarts temporarily clear the condition.

**Mitigation:** Give login and refresh distinct key strategies. For refresh, do not increment an account key derived from absent fields; use the IP bucket plus a privacy-preserving digest of the presented refresh token/session identifier, with a separate safe aggregate ceiling if desired. Add a regression test demonstrating 30 different refresh tokens do not lock out the 31st user while repeated use from one client is limited. A shared gateway/store remains necessary before horizontal scaling.

### DEP-01 — Medium — Deployment prerequisite validation runs before fetching the release being deployed

**Location:** `deploy.sh:16-27`; `deploy/check-deploy-prerequisites.sh`

**Evidence:** `deploy.sh` executes the checkout's current prerequisite script before validating the repository directory and before `git fetch`/`git pull`. It then deploys newly pulled nginx/application/scripts without rerunning the new release's prerequisite checks.

**Failure scenario:** A release changes certificate locations, tools, or deployment prerequisites. The prior checkout's checks pass, the new release is fetched, and deployment proceeds without validating the new contract.

**Impact:** A release can fail after migration/symlink work or install an nginx configuration whose prerequisites were never checked.

**Mitigation:** Perform only immutable bootstrap checks before fetch. After pulling and identifying the exact release commit, execute that release's `check-deploy-prerequisites.sh` before builds/migration/state changes. Pin deployment to an explicit commit/tag and log it.

### QA-01 — Medium — Backend and frontend lint gates remain nonfunctional

**Location:** `backend/package.json`, `frontend/package.json` and installed dependency/config state

**Evidence:** Backend `npm run lint` fails before analysis because ESLint 10 cannot find `eslint.config.*`. Frontend `npm run lint` fails because the local `eslint` executable is absent. These are the same toolchain gaps observed in the prior audit.

**Impact:** Static defects and unsafe patterns are not checked, and a release pipeline cannot truthfully gate on lint.

**Mitigation:** Pin compatible ESLint/typescript-eslint versions, add checked-in flat configuration for both projects, ensure lockfiles contain the tools, and enforce clean-install lint in CI.

### REL-01 — Low — APK provenance remains weaker than its UI claims

**Location:** `deploy/publish-rider-app.sh`, `deploy/app/index.html`, `frontend/src/i18n/locales/*/common.json`

**Evidence:** Publication now calculates SHA-256 and requires a text version sidecar, but does not inspect the APK manifest/version or verify the Android signing certificate. UI copy describes the release as signed/controlled while the publication process does not verify that property.

**Impact:** An incorrect locally supplied APK can be published with a matching mutable sidecar. This requires access to release inputs, so severity remains Low rather than a remote exploit.

**Mitigation:** Verify embedded package/version/versionCode and approved signing-certificate fingerprint before publication; generate a signed release manifest in CI and expose checksum/fingerprint to operators/riders.
