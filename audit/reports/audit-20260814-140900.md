## Findings

### High

**H-01 — Production refresh migration pending**

- **Location:** `backend/prisma/migrations-postgresql/20260814060000_refresh_tokens/migration.sql`
- **Evidence:** `RefreshToken` model and rotation logic exist; production Supabase must have the table before `/auth/refresh` works.
- **Impact:** Silent refresh fails; users hit session overlay every 15 minutes after deploy without migration.
- **Mitigation:** Run `npm run db:deploy:postgresql` against prod (session/direct URL on :5432) before enabling new API build.

**H-02 — Cross-region DB latency (Singapore VPS ↔ Mumbai Supabase)**

- **Location:** Infra; pooler host `aws-0-ap-south-1.pooler.supabase.com`
- **Evidence:** API on VPS in Singapore; Postgres in `ap-south-1`. Each Prisma query pays inter-region RTT.
- **Impact:** List/save/settlement endpoints with multiple queries feel slower than co-located DB; not a security issue.
- **Mitigation:** (1) Query/index optimization first. (2) Optional: new Supabase project in `ap-southeast-1` (Singapore) + dump/restore cutover — **cannot change region in place** ([Supabase docs](https://supabase.com/docs/guides/troubleshooting/change-project-region-eWJo5Z)). Static assets unaffected.

**H-03 — Dual refresh delivery (cookie + JSON body)**

- **Location:** `auth.controller.ts` sessionBody includes `refreshToken`; mobile stores in SecureStore; ERP must not persist JSON refresh.
- **Evidence:** ERP `setAuthToken(..., false)` on login; tests assert no `refreshToken` in localStorage. JSON still returned for mobile/tests.
- **Impact:** XSS on ERP cannot steal refresh from localStorage (good); stolen JSON refresh from mobile backup/debug remains a mobile threat surface.
- **Mitigation:** Keep ERP memory-only access token; document mobile SecureStore boundary; never add refresh to ERP localStorage.

**H-04 — Supabase pooler vs Serializable money posts (carry-forward D-05)**

- **Location:** `DATABASE_URL` / transaction pooler :6543 vs session :5432
- **Evidence:** Prior audit; money paths use Serializable transactions + advisory locks on Postgres.
- **Impact:** Transaction pooler mode can break Serializable semantics or migrations.
- **Mitigation:** App runtime on pooler with `pgbouncer=true`; migrations and deploy on direct :5432 URL.

### Medium

**M-01 — Legacy `lotaya_token` localStorage bootstrap**

- **Location:** `frontend/src/lib/api.ts` `getAuthToken()` falls back to localStorage
- **Evidence:** New logins use memory-only access token; old sessions may still read persisted JWT.
- **Impact:** XSS can exfiltrate legacy access tokens until users re-login; refresh not in localStorage.
- **Mitigation:** Migrate users through re-login; optionally clear `lotaya_token` on successful cookie refresh.

**M-02 — No proactive refresh timer on mobile**

- **Location:** `mobile/src/lib/api.ts` (401-triggered refresh only)
- **Evidence:** ERP schedules refresh ~60s before `expiresAt`; mobile refreshes on 401 / bootstrap.
- **Impact:** Rider may see brief 401/retry on first request after 15m idle; acceptable if retry works.
- **Mitigation:** Optional: schedule refresh from `expiresAt` on mobile parity with ERP.

**M-03 — Session overlay has no cancel/dismiss**

- **Location:** `frontend/src/components/session-expired-dialog.tsx`
- **Impact:** User must re-auth to proceed; draft preserved but blocked — by design for save flows.
- **Mitigation:** Acceptable for money workflows; optional “sign out” if product wants escape hatch.

**M-04 — `PROJECT_SPEC.md` drift on frontend auth**

- **Location:** Spec current-state blurb still mentions “persisted JWT authentication”
- **Impact:** Documentation misleads operators/reviewers.
- **Mitigation:** Spec Maintainer sync after intentional refresh design.

**M-05 — Ledger `take: 500` truncation (carry-forward)**

- **Location:** Finance ledger list endpoint
- **Impact:** Long history reports incomplete without date filters.
- **Mitigation:** Document in UI; paginate or export for full history.

### Low

**L-01 — Frontend test script duplicates `--run`**

- **Location:** `frontend/package.json` `"test": "vitest --run"` + `npm test -- --run` fails
- **Impact:** CI/docs confusion only; `npx vitest run` works.
- **Mitigation:** Remove redundant `--run` from npm script or docs.

**L-02 — Mobile login omits `remember`**

- **Location:** Mobile login request body
- **Impact:** Refresh TTL defaults to 12h session, not 7d remember.
- **Mitigation:** Add remember toggle if riders need longer sessions.

**L-03 — Refresh token table growth**

- **Location:** `RefreshToken` rows per login/rotation
- **Impact:** Unbounded rows over months.
- **Mitigation:** Scheduled cleanup of expired/revoked tokens (future hygiene).

## Positive controls verified

- Access JWT **15m**; refresh **12h / 7d remember**
- Refresh stored **hashed** (SHA-256); raw never in DB
- Reuse of revoked refresh → **revoke all** for user
- `tokenVersion` bump (password reset) → refresh family revoked (tested)
- Cookies: **HttpOnly**, **SameSite=Lax**, **Secure** in production, scoped **Path** `/` vs `/api/v1/auth`
- Login **rate limit** middleware on auth routes
- ERP **credentials: include** for cookie refresh
- Tests: `auth-refresh.test.ts` (6), `auth.test.tsx` (401/retry/overlay), mobile `api.test.ts` / `session-store.test.ts`
