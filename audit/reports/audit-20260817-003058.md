## Executive summary

Overall posture: **acceptable after remediation**. Initial review found High risks where paste could keep a cross-region `townshipId` while the township select looked empty and fee preview still rendered, plus catalog-load races leaving unresolved name tokens. Remediation syncs region from a uniquely resolved township on hydrate, scopes fee preview and save-readiness to region-consistent resolved IDs, re-hydrates rows when catalogs load, and refuses ambiguous township name matches without a scoping region.

## Findings

### Remediated — LOC-01 Cross-region paste binding (was High)

**Before:** `hydrateParcelRowLocations` preferred a valid pasted region even when the township belonged elsewhere; select filtered empty; fee cell used all townships; save still posted hidden `townshipId`.

**After:** Unique township resolution syncs `regionStateId` from the township’s district; fee cell and save gate require `isParcelRowLocationConsistent`.

### Remediated — LOC-02 Display vs state desync before catalogs load (was High)

**Before:** Paste before regions/townships loaded left name tokens; later `match()` could display resolved values while state still held tokens.

**After:** Hydrate no-ops without township catalog; `useEffect` re-hydrates non-blank rows when catalogs arrive; save blocked until `townshipId` is a known id.

### Remediated — LOC-03 Ambiguous township name match (was Medium)

**Before:** First-hit `match()` could bind the wrong region’s township.

**After:** Prefer unique hit within pasted region; otherwise require a globally unique hit; leave unresolved when ambiguous.

### Accepted — LOC-04 District column a11y (Low)

District is read-only text without `data-cell` / `aria-live`. Keyboard navigation skips former column 5. Acceptable for display-only helper field; no money impact.
