## Remediation verdict

### FIN-001 — Resolved

**Previous risk:** Medium
**Current risk:** Closed
**Locations:** `backend/src/services/parcel.service.ts:260-269`, `:1118-1165`, `:1168-1203`.

The shared `serializableTransaction` helper now converts the third `P2034` into `ApiError(409, "TRANSACTION_CONFLICT", ...)` instead of rethrowing the raw Prisma exception. Both `updateStatus` and `bulkUpdateStatus` recognize this domain error and pass it through `recoverStatusWriteConflict`.

The recovery order is appropriate:

1. It first checks whether every requested Paid-to-OS transition already reached the exact requested persisted state, including the linked-parcel COD-only fee rule, and returns the committed result without duplicating financial effects.
2. Otherwise it re-reads cashbook-day state outside the failed serializable transaction and returns `409 DAY_CLOSED` when applicable.
3. If neither condition applies, it returns stable `409 RETRYABLE_CONFLICT`.

This closes the ambiguous internal-error path while preserving transaction atomicity and idempotent concurrent replay behavior. No new authorization or financial-integrity regression was identified in the changed control flow.
