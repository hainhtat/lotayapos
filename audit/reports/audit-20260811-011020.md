# Lotaya POS — Final Release-Blocker Audit

**Timestamp:** 2026-08-11 01:10:20 +0630 (Asia/Yangon)  
**Scope:** Only the four requested release blockers: PostgreSQL migration deploy path, linked commission allocation/journal, linked shortfall scope, and mobile start-delivery behavior.  
**Repository context:** No `.git` metadata is available. No production code, tests, migrations, or configuration were modified.

## Verdict

**Three remediations are verified, but the linked/mobile workflow is not fully release-ready.** The PostgreSQL migration path is now correctly provider-specific; linked collection, commission, and shortfall journals are group-scoped and ledger scope recognizes them; and mobile exposes `ASSIGNED -> OUT_FOR_DELIVERY`. Two current High findings remain: concurrent final linked deliveries can leave all per-way commission allocations at zero, and “Start delivery” changes parcel status without creating the required open `DeliveryWay` audit record.

Finding count: **0 Critical, 2 High, 0 Medium, 0 Low**.

## Findings

### HIGH-FIN-01 — Concurrent linked completions can permanently skip per-way commission allocation

**Location:** `backend/src/services/parcel.service.ts:139-150`  
**Evidence:** Each delivery transaction updates one parcel, creates its zero-commission linked way, then allocates group commission only if its transaction can see every other member as `DELIVERED`. Under PostgreSQL's normal read-committed behavior, two final member transactions can each see the other's uncommitted old status, both skip allocation, and then both commit. There is no later allocator/reconciliation hook. Existing tests verify arithmetic only; they do not exercise concurrent database-backed completion.  
**Impact:** A fully delivered linked group can retain zero commission in every `DeliveryWay`, while settlement and the later commission journal use the nonzero adjusted group commission. The exact way-level audit trail disagrees with financial totals.  
**Mitigation:** Serialize group completion with a group row lock or serializable transaction/retry, or move allocation to an idempotent finalize-group command that can be retried after every completion. Add a concurrent PostgreSQL integration test and assert allocated ways sum exactly to the journal commission.

### HIGH-OPS-02 — Start delivery does not create/open a DeliveryWay

**Location:** `mobile/app/parcel.tsx:40`, `backend/src/services/parcel.service.ts:91-150`  
**Evidence:** Mobile now posts status `OUT_FOR_DELIVERY`, and the backend records only the parcel/status history for that transition. A `DeliveryWay` is created only at `DELIVERED`, using its default `startedAt` at completion time. Failed, Partial, and Rejected outcomes create no way at all.  
**Impact:** The system cannot audit attempt start time, preserve failed/partial/rejected ways, enforce “only while the way is open,” or calculate attempt-based operational metrics as specified. The UI transition works, but the underlying start-way workflow is absent.  
**Mitigation:** Implement an idempotent start-way transaction that creates one open way and moves the parcel to `OUT_FOR_DELIVERY`; finalize that same way for every terminal outcome. Enforce one open way per parcel and test retry/concurrency behavior.

## Verified fixes

- `prisma.config.ts` selects `prisma/migrations-postgresql` whenever `DATABASE_PROVIDER=postgresql`; its lock file declares `postgresql` and the baseline uses PostgreSQL-native DDL covering current models, indexes, and foreign keys.
- `db:deploy:postgresql` sets the provider and uses the PostgreSQL schema; Prisma schema validation passes with the provider-specific configuration.
- Linked finance posting uses `LINKED_DELIVERY_COLLECTION + group.id`, checks that all group members are delivered, uses aggregate COD/advance and adjusted fee limits, and posts atomically.
- Linked commission posts balanced `RIDER_COMMISSION_EXPENSE` / `RIDER_COMMISSION_PAYABLE` lines under `LINKED_RIDER_COMMISSION + group.id`.
- Linked shortfall uses its own `LINKED_OS_SHORTFALL + group.id` key.
- Ledger report/reversal scope resolves linked collection, linked commission, and linked shortfall through every member's hub.
- Mobile passes current parcel status, shows “Start delivery” only for `ASSIGNED`, posts `OUT_FOR_DELIVERY`, and exposes outcomes only after the transition succeeds.
