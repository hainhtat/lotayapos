## Findings (by severity)

### AUD-20260815-01 — `MONEY_POSTED` ignores versioned linked-group journals

| | |
| --- | --- |
| **Risk** | **High** |
| **Location** | `backend/src/services/parcel.service.ts` — `findUnreversedMoneyPostedEntry` |
| **Evidence** | Linked branch matches only `sourceId: input.linkGroupId`. After `8f78d0c`, live `LINKED_RIDER_COMMISSION` / `LINKED_RIDER_RECEIVABLE_FEE` / etc. may use `groupId:<uuid>`. Parcel-scoped `startsWith` does not cover group-scoped keys. Spec §6 explicitly requires the gate to consider group-scoped (including versioned) `LINKED_*` journals. |
| **Impact** | Ops can override a linked parcel out of `DELIVERED`/`PARTIAL` while unreversed linked fee/commission/collection journals remain → receivable/commission leave orphaned against wrong operational status. |
| **Mitigation** | Mirror parcel logic: for `linkGroupId`, query `OR: [{ sourceId: linkGroupId }, { sourceId: { startsWith: \`${linkGroupId}:\` } }]` for `LINKED_MONEY_POSTED_SOURCE_TYPES` (keep `LINKED_RIDER_RECEIVABLE_COD` on parcel id path). Add regression test: reverse base linked fee, re-post versioned, assert override still `409 MONEY_POSTED`. |

### AUD-20260815-02 — Reversed partial-return journals block silent re-post

| | |
| --- | --- |
| **Risk** | **High** |
| **Location** | `backend/src/services/parcel.service.ts` — `updateStatus` PARTIAL path (`PARTIAL_RETURN_COLLECTION`, `OS_PARTIAL_RETURN_ADJUSTMENT`) |
| **Evidence** | `findUnique` on fixed `sourceId: id`; if row exists, create is skipped with **no** `journalEntryIsUnreversed` check. Spec lists these types in the Money-Posted set and expects corrections via reversal then operational re-entry; versioned re-post helper was applied to commission/receivable/advance/`LINKED_*` but not these two. |
| **Impact** | After Finance reverses partial journals and Ops re-marks `PARTIAL`, wallet collection / OS shortfall offset are not re-posted → understated cash and OS receivable vs parcel state. |
| **Mitigation** | Use `nextVersionedJournalSourceId` (and unreversed checks) for both source types before create; extend hub-scope parsers to `split(":")[0]` for these types; regression: reverse → re-PARTIAL posts new balanced journals. |

### AUD-20260815-03 — Delivery collection not re-postable after reversal; linked path can double commission

| | |
| --- | --- |
| **Risk** | **High** |
| **Location** | `backend/src/services/ledger.service.ts` — `postDeliveryCollection` |
| **Evidence** | (1) `existing` on fixed `parcelId`/`groupId` throws `COLLECTION_EXISTS` even if reversed. (2) Linked branch always `create`s `LINKED_RIDER_COMMISSION` with `sourceId: group.id`. Delivery already posts that type via `nextVersionedJournalSourceId`. After reverse + versioned re-post at delivery, collection can create a **second live** base-key commission journal. |
| **Impact** | Cannot re-collect after corrective reverse; or duplicate commission expense/payable → inflated rider payable and settlement distortion. |
| **Mitigation** | Treat collection like other money events: versioned sourceIds + unreversed existence checks; **do not** post `LINKED_RIDER_COMMISSION` from collection if delivery-time posting is canonical (or share one allocator and skip when any live commission exists for the group). Use serializable tx. Tests for reverse→re-collect and no double commission. |

### AUD-20260815-04 — Linked group completion can divide by zero or mis-allocate across historical DELIVERED ways

| | |
| --- | --- |
| **Risk** | **Medium** |
| **Location** | `backend/src/services/parcel.service.ts` — linked finalization; `finance.service.ts` `settlementWork` display mapping |
| **Evidence** | `Math.floor(totalCommission / ways.length)` with `ways = DeliveryWay where outcome: "DELIVERED"` for all group members. No empty guard. Re-delivery after status correction leaves prior `DELIVERED` ways intact while creating another → inflated denominator. `settlementWork` uses `.find(outcome === "DELIVERED")` without preferring latest way. `correctDeliveredRider` `updateMany` rewrites **all** `DELIVERED` ways’ rider/commission. |
| **Impact** | Runtime failure on empty ways; per-way commission UI wrong; historical way audit rewritten on rider correction. Recognition aggregates remain primary for cash expected amounts. |
| **Mitigation** | Allocate using one canonical DELIVERED way per parcel (latest `completedAt`); guard `ways.length === 0`; on re-outcome supersede prior DELIVERED ways (e.g. outcome `SUPERSEDED`/`REPLACED`); scope rider correction to the active way only. |

### AUD-20260815-05 — `postPickupAdvances` allocates versioned `sourceId` outside the posting transaction

| | |
| --- | --- |
| **Risk** | **Medium** |
| **Location** | `backend/src/services/operations.service.ts` — `postPickupAdvances` |
| **Evidence** | `nextVersionedJournalSourceId(prisma, …)` runs before `$transaction`. Concurrent posters can share one key; P2002 handler returns `alreadyPosted` only if collision is unreversed, otherwise rethrows. If collision row is reversed, client gets a raw uniqueness failure instead of retry with a new UUID. Transaction is not serializable. |
| **Impact** | Rare duplicate-attempt races → failed finance UX / possible operator double-clicks after reverse without clear idempotent success. |
| **Mitigation** | Allocate + create inside a serializable transaction; on P2002 with reversed collision, loop with a fresh versioned id (bounded retries). |

### AUD-20260815-06 — Hub-scope parsers incomplete for non-split parcel money types if versioned later

| | |
| --- | --- |
| **Risk** | **Low** (latent; becomes High if AUD-02/03 ship versioning without scope fix) |
| **Location** | `ledger.service.ts` — `assertOriginalScope` / `entryInScope` |
| **Evidence** | Only `OS_RETURN_DEDUCTION`, `RIDER_COMMISSION`, `RIDER_RECEIVABLE_RECOGNITION`, `LINKED_RIDER_RECEIVABLE_COD` split `sourceId` on `:`. `DELIVERY_COLLECTION`, `PARTIAL_RETURN_*`, `OS_SHORTFALL` still treat full `sourceId` as parcel id. |
| **Impact** | Versioned collection/partial keys would fail hub lookup → finance reverse/list incorrectly `FORBIDDEN` or out-of-scope. |
| **Mitigation** | Always parse base id as `sourceId.split(":")[0]` for parcel-scoped money types when introducing versioning. |

### AUD-20260815-07 — Postgres pool disables TLS certificate verification

| | |
| --- | --- |
| **Risk** | **Medium** (residual / infra) |
| **Location** | `backend/src/config/postgres-pool.ts` — `ssl: { rejectUnauthorized: false }` |
| **Evidence** | Unconditional for pooled connections. |

## Performance / reliability / scalability observations

1. **`listBatches` advance lookup** builds one `OR` `startsWith` clause per batch (up to 200) and then `await journalEntryIsUnreversed` sequentially per hit — acceptable at current caps; will degrade if caps rise. Prefer a single query joining reversals or batched unreversed checks.
2. **`nextVersionedJournalSourceId`** only inspects the latest **20** versioned rows; pathological histories with an older live entry could allocate another live key (Low probability). Prefer “any unreversed for base prefix” without `take: 20`.
3. **DeliveryWay** has no DB uniqueness for “at most one open way per parcel”; correctness relies on serializable `updateStatus`. Other writers creating ways outside that path would race (none found in services grep beyond `updateStatus` / tests / correct-rider updates).
4. **OS settlement / rider settlement** posting uses Serializable isolation and live re-checks — positive control.
5. **Cashbook close** gates on variance approval and wallet reconciliation — positive control; not re-proven under concurrent close+post in this audit.
