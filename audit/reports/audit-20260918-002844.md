# Targeted Audit — Rider Payments, OS Fee Credits, Pending Return, and PDFs

**Timestamp:** 2026-09-18 00:28:44 +0630 (Asia/Yangon)  
**Scope:** Current changed files affecting rider payment/date presentation, legacy OS fee-credit conditions, Pending Return reason capture, and manifest/return-handover PDF output.  
**Method:** Reviewed `PROJECT_SPEC.md`, inspected the working-tree diff and relevant server/client call paths, and ran focused backend tests and typecheck. No production code was modified.

## Executive summary

The OS fee-credit condition and Pending Return reason workflow match the current specification. Rider receipt queries are correctly exact-date scoped while outstanding balance is cumulative through the selected date. Three current regressions remain: the Return-to-OS PDF shows a fee that its own row total and document total exclude; all assignment manifests were unintentionally changed from portrait to landscape; and the settlement screen derives its default business date from UTC rather than the configured hub-local date.

Finding count: **0 Critical, 0 High, 3 Medium, 0 Low**.

## Findings

### MED-FIN-01 — Return handover rows display excluded delivery fees

**Location:** `backend/src/utils/manifest-pdf.ts:394-426`  
**Evidence:** For a Return-to-OS handover with `paidToOsFeeIncluded !== true`, row `total` correctly excludes the fee and `totalsFor()` correctly contributes zero fees. However, the row's Fee column always renders `money(fee)` at line 425. A 36,000 COD / 4,000 fee parcel therefore prints Fee 4,000, Total 36,000, while the summary also reports Fees 0.  
**Impact:** The financial handover document is internally contradictory and can cause the OS or operations team to treat a non-creditable fee as payable/credited.  
**Mitigation:** Derive one `includedFee` value (`returnHandover && !paidToOsFeeIncluded ? 0 : fee`) and use it for the Fee column, row Total, and document totals. Add a PDF text assertion for both fee-included and fee-excluded return parcels.

### MED-REL-02 — PDF orientation change affects every manifest, not only Return to OS

**Location:** `backend/src/utils/manifest-pdf.ts:49-75`  
**Evidence:** `PAGE_WIDTH`/`PAGE_HEIGHT` and the landscape column layout are global. `buildPdfDocument()` uses them for ordinary rider assignment sheets as well as Return-to-OS handovers. The specification explicitly calls for the Return-to-OS handover to use the new landscape/wrapped layout; the prior active rider sheet was A4 portrait. Current tests assert landscape only for Return-to-OS but do not assert ordinary manifest dimensions.  
**Impact:** Existing assignment manifests silently change print format, reducing compatibility with established portrait printing and potentially breaking operational paper workflows.  
**Mitigation:** Select page dimensions/column definitions by document type, keeping active rider sheets portrait and Return-to-OS handovers landscape. Add page-dimension regression tests for both document types.

### MED-FIN-03 — Default rider-payment business date uses UTC, not hub-local date

**Location:** `frontend/src/pages/settlement-workspaces.tsx:39,47`  
**Evidence:** The selected/default date is `new Date().toISOString().slice(0,10)`. In Asia/Yangon between local midnight and 06:29, this returns the previous UTC calendar date. That value scopes `/finance/rider-outstanding` and is submitted as the rider receipt `businessDate`. The backend correctly treats the submitted value as an exact business date, so the UI error is preserved in accounting.  
**Impact:** Early-morning users can see yesterday's expected/received figures and accidentally post a rider receipt to yesterday; if yesterday is closed the action fails, and if it is open the cashbook/day reporting is misdated.  
**Mitigation:** Obtain the canonical business date from the backend/hub context or format the current instant in the configured hub timezone. Use the same helper for URL defaults and OS/return dates, and test around 00:00–06:29 Yangon time.

## Resolution rerun — 2026-09-18 00:35 +0630

The three findings above are retained as historical audit evidence but are **resolved in the current working tree**. Current scoped finding count: **0 Critical, 0 High, 0 Medium, 0 Low**.

The Finance wallet-adjustment workflow, cashbook expense workflow, and detailed report date defaults also use `hubBusinessDate()`. The helper formats dates in `Asia/Yangon`, and its tests cover UTC instants that cross the Yangon calendar-day boundary.
