## Executive summary

Overall risk posture for the rider mobile client is **Medium–High** for **production field use**, driven primarily by **session lifetime mismatch** (backend JWT **15 minutes**, no refresh, no mid-session 401 → logout) and **cleartext HTTP defaults** suitable for Expo Go LAN testing but unsafe if shipped. Privilege escalation via the stock UI is **not** evidenced: assignment list, parcel detail, status updates, and settlement declare/preview are **server-scoped** to the rider. Client-side COD/reason validation is UX-only; the API re-validates. Residual risks: non-`RIDER` accounts can obtain an elevated JWT through this login surface; parcel list is capped at default page size 50 with no client pagination; dependency pins use `"latest"`; deep-link scheme is declared without production intent-filter hardening docs.

**Finding counts:** Critical **0**, High **2**, Medium **5**, Low **3**.

## Findings

### AUD-MOB-01 — High — Access token expires in 15m with no refresh and no global 401 handling

**Location:** `backend/src/utils/jwt.ts` (`expiresIn: "15m"`); `mobile/src/providers/auth.tsx`; `mobile/src/lib/api.ts`; `mobile/src/lib/query-retry.ts`

**Evidence:** Login stores Bearer JWT (SecureStore when “Remember me”). Auth bootstrap calls `/auth/verify` only once on mount. `api()` surfaces `ApiError` on failure; queries skip retry on 401 but **do not** clear the session or navigate to login. There is no refresh-token or sliding-session path in the mobile client.

**Failure scenario:** Rider signs in, works the route for >15 minutes, then posts an outcome or saves a settlement declaration. Requests return 401; UI still shows authenticated tabs; saves fail with raw/generic errors until force quit / manual logout / cold start (verify then clears token).

**Impact:** Field reliability failure during cash collection / outcome posting; operators may retry blindly; “Remember me” does not provide a durable session beyond JWT TTL.

**Mitigation:** Add refresh tokens or longer rider-device session policy with server revocation (`tokenVersion`); on any 401 from `api()`, clear SecureStore/memory token, reset auth state, and route to login. Align product copy so “Remember me” means identifier (and optional refresh), not an immortal access token.

### AUD-MOB-02 — High — Default / documented API base URL is cleartext HTTP (LAN-friendly)

**Location:** `mobile/src/lib/api.ts` (`EXPO_PUBLIC_API_BASE_URL??"http://localhost:4000/api/v1"`); `mobile/.env.example`; `mobile/app.json` (no ATS / `usesCleartextTraffic` / HTTPS-only policy)

**Evidence:** Default and example env use `http://` including LAN IP guidance for physical Android + Expo Go. `app.json` has no production networking hardening. No `eas.json` / release channel config was present.

**Failure scenario:** A release or sideload build points at a cleartext LAN or staging host. On shared Wi‑Fi, JWT + customer PII (name, phone, address, COD) in JSON are observable. Android/iOS production policies may also block or inconsistently allow cleartext vs Expo Go.

**Impact:** Credential and customer PII interception; confusion between Expo Go test path and production posture.

**Mitigation:** Require `https://` for non-dev builds (fail fast if scheme is `http` outside `__DEV__`); document TLS termination; keep LAN HTTP as an explicit opt-in with warning; add Android cleartext allowlist only for debug flavors.

### AUD-MOB-03 — Medium — Non-rider roles can sign in and store an elevated JWT on the device

**Location:** `mobile/src/providers/auth.tsx` (`signIn` accepts any `/auth/login` success); `backend/src/services/auth.service.ts` (no client/audience role filter)

**Evidence:** Mobile never checks `user.role === "RIDER"` before `setAccessToken` / navigation. Server still denies `assignedToMe` and rider declaration for non-riders, but the issued JWT carries the real role (`SUPERADMIN`, `FINANCE`, `DISPATCHER`, etc.).

**Failure scenario:** Staff credentials are used on a shared rider phone (or phishing into this app). Token extracted from SecureStore/memory can call privileged ERP APIs until expiry/revocation—far beyond rider UI affordances.

**Impact:** Concentrates high-privilege tokens on lightly supervised field devices; not a UI privilege escalation, but a token-handling / product-boundary defect.

**Mitigation:** After login/verify, require `role === "RIDER"` (and active rider profile) or reject with a dedicated error; optionally mint audience-scoped tokens (`aud: rider-app`) enforced in `requireAuth`.

---

### AUD-MOB-04 — Medium — Mid-session auth failures and logout do not revoke Bearer JWTs

**Location:** `backend/src/controllers/auth.controller.ts` (logout clears HttpOnly cookie only); mobile uses `Authorization: Bearer`

**Evidence:** Logout succeeds locally via `clearAccessToken`; server logout does not bump `tokenVersion`. Stolen/copied Bearer remains valid until the 15m JWT expiry.

**Failure scenario:** Rider logs out on a borrowed device; an attacker who already copied the token continues calling rider APIs briefly. Combined with longer future TTLs, impact grows.

**Impact:** Incomplete session termination for mobile Bearer clients.

**Mitigation:** Increment `tokenVersion` (or maintain a denylist) on logout; ensure mobile always sends Bearer and treats logout as server-authoritative revocation.

---

### AUD-MOB-05 — Medium — Assigned parcel list ignores pagination (silent truncation at 50)

**Location:** `mobile/src/lib/api.ts` `getAssignedParcels()` → `GET /parcels?assignedToMe=true`; `backend` list default `pageSize` 50, max 100

**Evidence:** Client maps `data` as a full array and never reads `pagination` or requests further pages.

**Failure scenario:** Busy rider has >50 open assignments. Home route under-counts; parcels beyond page 1 never appear; outcomes/settlement expectations diverge from reality.

**Impact:** Operational miss / missed collections; trust erosion in “assigned” hero count.

**Mitigation:** Request `pageSize=100` and loop pages until exhausted (or server “assigned route” endpoint without arbitrary truncation); surface total from `pagination.total`.

---

### AUD-MOB-06 — Medium — Settlement business date is device-local, while server normalizes as UTC midnight

**Location:** `mobile/src/lib/settlement.ts` `localBusinessDate()`; `backend/src/services/finance.service.ts` `businessDay()` (`setUTCHours(0,0,0,0)` on parsed date)

**Evidence:** Mobile sends `YYYY-MM-DD` from `Date#getFullYear/Month/Date` (device TZ). Server parses and anchors UTC. Near timezone boundaries (Myanmar UTC+6:30 vs UTC), “today” can disagree with hub cashbook day.

**Failure scenario:** Late-evening declaration lands on an unexpected `businessDate`, conflicting with finance posting or day-close.

**Impact:** Settlement declaration attached to wrong day; ops reconciliation pain (money risk if finance posts against mismatched preview).

**Mitigation:** Agree hub timezone (e.g. Asia/Yangon) on server; return canonical `businessDate` from preview; mobile should not invent the date unilaterally (or send offset explicitly).

---

### AUD-MOB-07 — Medium — Unpinned `"latest"` dependencies and Expo Go–centric runtime

**Location:** `mobile/package.json` (nearly all deps `"latest"`); lockfile currently resolves Expo 57 / RN 0.86; no `eas.json`; host has no Android SDK (Expo Go path per context)

**Evidence:** Reproducible builds depend solely on lockfile discipline; `"latest"` invites surprise majors on fresh `npm install`. Expo Go lacks production entitlements, cleartext policy parity, and update discipline of store builds.

**Failure scenario:** CI or a new machine resolves different majors; SecureStore / Router behavior shifts; field testers assume Expo Go ≈ production security.

**Impact:** Supply-chain and release reproducibility risk; false confidence in security controls.

**Mitigation:** Pin semver ranges to tested versions; add EAS production profiles; treat Expo Go as dev-only in runbooks.

---

### AUD-MOB-08 — Low — Deep link scheme `lotayarider` declared without explicit link allowlisting

**Location:** `mobile/app.json` `"scheme":"lotayarider"`; routes via Expo Router + `Stack.Protected`

**Evidence:** Scheme is registered; auth guards hide `login` vs `(tabs)`/`parcel`. No custom universal-link / intent-filter documentation, no validated path allowlist beyond Router. Parcel `id` comes from `useLocalSearchParams` and is server-scoped on fetch/update.

**Failure scenario:** Malicious `lotayarider://parcel?id=…` opens detail when a session exists; unassigned IDs 404 from API. Unauthenticated deep links should hit protected stack (not verified on device in this audit).

**Impact:** Limited; mainly phishing/confusion rather than authz bypass if server scope holds.

**Mitigation:** Document supported deep-link paths; reject unexpected hosts/paths; verify Protected behavior on iOS/Android builds; prefer HTTPS app links for production.

---

### AUD-MOB-09 — Low — API error messages rendered directly in UI

**Location:** `mobile/app/login.tsx`, `mobile/app/parcel.tsx`, `mobile/app/(tabs)/settlement.tsx` (`e instanceof Error ? e.message`); `mobile/src/lib/api.ts` maps `body?.error?.message`

**Evidence:** Backend `errorHandler` does not attach stacks (good). Messages are still server strings (transition text, validation). Login shows them instead of always using `loginError` i18n.

**Failure scenario:** Verbose validation/transition messages leak internal status vocabulary; unexpected 500 still generic on server, but any future detail enrichment would display immediately.

**Impact:** Minor information disclosure / inconsistent i18n (en/my).

**Mitigation:** Map stable `error.code` to localized strings; keep raw message for debug builds only.

---

### AUD-MOB-10 — Low — `mobile/.gitignore` does not ignore `.env`; hardcoded EN copy in outcome UI

**Location:** `mobile/.gitignore` (Expo-generated only); `mobile/app/parcel.tsx` label `"Collection wallet"`

**Evidence:** No `.env` ignore rule under `mobile/`; LAN URLs in `.env` could be committed if present. Partial wallet label bypasses i18n (spec: en/my).

**Impact:** Accidental secret/URL commit; Myanmar users see English fragment.

**Mitigation:** Ignore `.env*` (keep `.env.example`); move string to locale files.

## Positive controls verified

- No client JWT decode for authz; session user comes from `/auth/verify` or login payload; money/status mutations always hit API.
- Rider parcel list uses `assignedToMe=true`; detail/history/update use server `buildParcelScope` / `assertParcelAccess` (rider must own assignment).
- Outcome client validation (reason, note, COD ≤ original, wallet) mirrored server-side (`REASON_REQUIRED`, configured reason codes, `COLLECTION_EXCEEDS_PARCEL`, wallet required for PARTIAL).
- Settlement **declare** route is `requireRoles("RIDER")`; `resolveSettlementRider` blocks cross-rider IDs for riders. Hub posting remains finance roles.
- Password not stored; remember persists identifier + optional token only (`session-store.test.ts`, login tests).
- Auth navigation uses `Stack.Protected` guards (`auth-navigation`).
- Backend errors omit stacks; mobile unit suite **41/41 passed** (`npm test` in `mobile/`).

## Unverified areas, limitations, and follow-up

- Device confirmation of deep-link + Protected routing, SecureStore hardware backing, and Android cleartext on a release APK (no SDK on host).
- Whether production will terminate TLS and what CORS origins Expo Go uses in the field.
- Rider-specific **server** allowlist of destination statuses beyond the shared transition table (e.g. crafted `PARTIAL` → `PENDING_RETURN`) — not exercised here; recommend explicit rider outcome enum on the API.
- Token theft via compromised Expo Go / debug builds.
- End-to-end MitM on LAN HTTP during Android testing.

**Recommended follow-up checks:** instrumented 16+ minute session test; HTTPS fail-closed build flag; role gate on login; paginated assigned route; hub timezone contract for settlement dates; EAS production profile + pinned deps; optional `/auditor` revisit after refresh-token work.
