## Findings

### Critical

- **D-01 HTTP-only nginx.** `deploy/nginx/lotaya.mmds.site.conf` listens on 80. Production cookies/`Secure` and PII must not stay on cleartext. **Mitigation applied after review:** first deploy HTTP then Certbot; `deploy.sh` does not overwrite a site file that already `listen 443`.

### High

- **D-02 API bind.** `app.listen` defaulted all interfaces / port 4000. **Mitigation:** `LISTEN_HOST` defaults to `127.0.0.1` in production; systemd sets `PORT=4010` and `LISTEN_HOST=127.0.0.1`.
- **D-03 PDF inflate DoS.** Inflating every stream. **Mitigation:** only `/FontFile2` lookbehind + `maxOutputLength` 8 MiB.
- **D-04 APK sideload.** Any http(s) `apkUrl`. **Mitigation:** HTTPS + host `lotaya.mmds.site` + `.apk` path. Unsigned sideload remains an accepted product choice (no Play Store).
- **D-05 Prisma + Supabase transaction pooler (:6543).** Use `pgbouncer=true` on the pooler URL and a session/direct URL on 5432 for `migrate deploy`. Do not share one transaction-pool URL for migrations and Serializable money posts.
- **D-06 Unbounded ledger.** `GET /finance/ledger` had no `take`. **Mitigation:** `take: 500`.

### Medium

- Oversize PDF could 500 before service `413`. **Mitigation:** map Express `entity.too.large` to `413 PAYLOAD_TOO_LARGE`.
- `WEB_ORIGIN` must be set to `https://lotaya.mmds.site` in shared env (not localhost).
- `trust proxy` now set in production so login rate-limit sees client IPs.

### Low

- TTF parsers still assume well-formed tables; failures become `INVALID_PDF`.
- Temp PDF file is written then unused (spec hygiene).
- No APK is built by `deploy.sh`; download 404s until `releases/lotaya-rider.apk` exists.

## Verified non-issues for this deploy shape

- nginx `server_name lotaya.mmds.site` is not `default_server` and `deploy.sh` only installs that vhost file.
- Manifest import is role/hub gated, local-only, does not auto-create parcels.
- JWT role is re-checked from DB.
