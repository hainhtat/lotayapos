## Executive summary

Overall posture: **caution — availability risk elevated by the new Myanmar drawing path**. Separating Status from exception notes and hardening download filenames/CORS expose are sound product/security improvements. The dominant new risk is **authenticated CPU/memory exhaustion**: each Myanmar run is shaped with fontkit then drawn as many `drawSvgPath` calls, while the full Noto font is still embedded unused. At the existing 500-parcel / 50-rider caps, Myanmar-heavy sheets can block the Node event loop and inflate PDF size; there is no dedicated rate limit or worker isolation on the manifest endpoint.

Filename sanitization and RFC 5987 disposition look **safe**. Status codes are no longer incorrectly stuffed into the Note column for dispatch-ready rows; exception freeform notes now appear intentionally for FAILED/PARTIAL/REJECTED/PENDING_RETURN — with residual leakage via **unbounded** preview JSON note strings.

## Findings (by severity)

### AUD-20260815-PDF-01 — Per-glyph SVG Myanmar drawing enables CPU/PDF-size DoS at cap

| | |
| --- | --- |
| **Risk** | **High** |
| **Location** | `backend/src/utils/manifest-pdf.ts` — `drawShapedMyanmar`, `flipFontkitSvgPathY`, `drawText`, `buildPdfDocument`; route `POST /operations/parcels/manifest` |
| **Evidence** | Any string matching `MYANMAR_RE` skips `PDFFont.drawText` and instead: `font.layout(text)` → per glyph `path.toSVG()` → regex/number rewrite → `page.drawSvgPath(...)`. Row fields (customer, address, township, shop, rider header, notes) commonly contain Myanmar in production. Caps remain 500 parcels / 50 riders (`buildManifestForRiders`). Endpoint is authenticated but **not** rate-limited (only login/refresh share `auth-rate-limit`). Generation is synchronous on the request path (`generateDispatchManifestPdf` → `doc.save()`). Prior implementation used embedded-font `drawText`; this path is asymptotically heavier (path ops × glyphs × rows) and grows content streams far beyond subsetted text. |
| **Impact** | A Dispatcher/OM/Finance/Auditor (or stolen JWT) can repeatedly request max-size Myanmar manifests and stall or OOM the API process, denying service to other hubs. Large responses also stress proxies and browsers. |
| **Mitigation** | Prefer embedding `NotoSansMyanmar` and drawing with pdf-lib/`fontkit` text APIs (or a worker + timeout) instead of per-glyph SVG. Add request rate/concurrency limits for manifest PDF; optional soft timeout; consider lower parcel caps or async job + download for large Myanmar sheets. Add a load test at 500 Myanmar rows. |

### AUD-20260815-PDF-02 — Unused font embed stacks cost on top of SVG paths

| | |
| --- | --- |
| **Risk** | **Medium** |
| **Location** | `backend/src/utils/manifest-pdf.ts` — `buildPdfDocument` (`await doc.embedFont(myanmarBytes)` discard; `fontkit.create(myanmarBytes)` used only for SVG) |
| **Evidence** | Font file is ~195 KB on disk (`backend/assets/fonts/NotoSansMyanmar-Regular.ttf`). Bytes are read (cached), **embedded** into every PDF, and separately parsed by fontkit for layout/SVG. Drawn Myanmar never uses the embedded `PDFFont`. Spec §6.3 still requires shipping the font asset; embedding without using it for text draws adds parse/subset CPU and PDF bloat on every download. |
| **Impact** | Amplifies AUD-20260815-PDF-01: higher latency, memory, and download size even for modest sheets. |
| **Mitigation** | Either (a) use the embedded font for `drawText` and delete the SVG path renderer, or (b) if SVG must stay, stop embedding the unused font. Keep asset packaging for whichever path remains. |

### AUD-20260815-PDF-03 — Exception notes unbounded in preview JSON; status `note` input uncapped

| | |
| --- | --- |
| **Risk** | **Medium** |
| **Location** | `backend/src/services/operations.service.ts` — `exceptionNoteFromHistory`, section mapping; `backend/src/controllers/operations.controller.ts` — `previewManifest`; `backend/src/validators/parcels.ts` — `body("note").optional().isString().trim()` (no `isLength`); PDF `fit(noteText \|\| "-", 8)` |
| **Evidence** | For `FAILED` / `PARTIAL` / `REJECTED` / `PENDING_RETURN`, preview/PDF sections set `note` from latest exception `statusHistory.note` or `reasonCode` (else parcel `reasonCode`). PDF truncates display to 8 characters; **preview JSON returns the full string**. Parcel status validation does not cap note length (unlike settlement notes max 500). Finance/Auditor roles may call preview per spec for daily delivery status including exception statuses. |
| **Impact** | (1) Confidential freeform rider/ops notes (and long override text) leave the parcel record into browser memory, network logs, and screen share during Reports/Dispatch preview. (2) A crafted multi-megabyte note stored earlier can inflate preview responses (availability / memory). Physical PDF leakage is limited by `fit(..., 8)` but still shows a snippet of exception text under Status. |
| **Mitigation** | Cap `note` on status APIs (e.g. 500). Truncate or omit freeform notes in preview unless explicitly requested; prefer reason codes on printed rider sheets. Document intentional Finance visibility in the spec if full notes remain. |

### AUD-20260815-PDF-04 — CORS `exposedHeaders` widens readable metadata (intentional, residual)

| | |
| --- | --- |
| **Risk** | **Low** |
| **Location** | `backend/src/middleware/core.ts` — `exposedHeaders: ["Content-Disposition", "X-Rider-Count", "X-Parcel-Count", "x-request-id"]` |
| **Evidence** | SPA downloads read `Content-Disposition` via `resolveManifestPdfFilename` (`operations-page.tsx`, `reports-page.tsx`). Without expose, browsers hide the header from JS. Counts were already set on the PDF response; they are now readable cross-origin to allowlisted `WEB_ORIGIN`s with credentials. |
| **Impact** | Necessary for correct download names. Residual: allowlisted scripts learn rider/parcel counts and request IDs for manifest calls (not parcel PII). Misconfigured broad CORS origins would expand that surface. |
| **Mitigation** | Keep expose list minimal (current list is reasonable). Ensure production `webOrigins` stay strict. Prefer deriving download name only from `Content-Disposition`, not from count headers. |

### AUD-20260815-PDF-05 — Filename sanitization is effective; residual only if helpers are bypassed

| | |
| --- | --- |
| **Risk** | **Low** (residual / defense-in-depth note) |
| **Location** | `operations.service.ts` — `sanitizeManifestFilenamePart`, `buildManifestFilenameSuffix`; `operations.controller.ts` — ASCII fallback + `filename*` |
| **Evidence** | Rider name segment is lowercased and reduced to `[a-z0-9-]` (max 60), else `"rider"`. Suffix templates use Yangon `YYYY-MM-DD` and numeric rider counts. Controller quotes ASCII filename and adds `filename*=UTF-8''` + `encodeURIComponent`. Frontend parser prefers `filename*` then quoted `filename`, with tests. Myanmar-only rider names collapse to `lotaya-manifest-rider-<date>.pdf` (usability, not injection). |
| **Impact** | No confirmed Content-Disposition injection, path traversal, or header CRLF from current suffix construction. Risk would reappear if a future caller puts unsanitized Unicode/quotes into `filenameSuffix`. |
| **Mitigation** | Keep a single `buildContentDisposition(filename)` helper that always sanitizes before quote/`filename*`. Reject suffixes outside `^[a-z0-9._-]+$` in the controller. |

## Performance / reliability / scalability observations

- **Event-loop coupling:** PDF build + `save()` runs inline in Express; Myanmar SVG path expansion is the new hotspot (worse than prior embedFont `drawText`).
- **Caps help but do not neutralize:** 500× multi-column Myanmar still allows large work units; concurrent downloads multiply load.
- **Prisma:** Exception note fetch uses per-parcel `statusHistory` include `take: 1` — not an N+1 query storm; acceptable at cap.
- **Font I/O:** `loadMyanmarFontBytes` caches in process memory — good; does not mitigate SVG CPU.
- **Pagination of PDF:** Multipage continuation exists; does not reduce total work for the request.
- **Frontend:** `content-disposition` parsing is pure and tested; download uses blob URL — fine once CORS expose is present.
